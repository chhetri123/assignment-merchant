Explain `$ARGUMENTS` as if I were about to defend it in the review interview.

Read the code first, then cover:

- What it does and where it lives.
- Why it is built this way, and what the alternatives were.
- The trade-off a reviewer is most likely to challenge, and the honest answer.
- Where it is tested, and whether that test has been shown to fail when the behaviour
  is broken.

Be concrete and cite `file:line`. If something is weak, say so rather than defending it.
